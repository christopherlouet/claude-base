# Plan: counts.json source of truth + CI gate

**Branch**: `feature/counts-source-of-truth`
**Date**: 2026-05-03
**Spec**: [spec.md](./spec.md)
**Status**: Validated

## Summary

Add `counts.json` at repo root, generated by extending the existing `website/scripts/generate-*.ts` pipeline. Refactor 5 TS files to import from it, instrument 7 Markdown files with HTML-comment markers, fix 1 stale CI YAML string, and add a CI gate that runs the regenerator + `git diff --exit-code`.

Existing infrastructure:
- `validate-counts.sh` (410 LOC, 3 layers, mature) — keep Layer 2 (global narrative scan), prune Layers 1 redundant with the new gate
- `generate-all.ts` already runs on every `npm run build` and computes per-domain totals dynamically (`generate-command-docs.ts:216`) — natural place to plug in `counts.json` writer
- `tests/validate-counts.bats` (19 tests) — must stay green; some Layer 1 tests will be retired

## Technical context

| Aspect | Choice | Notes |
|---|---|---|
| Language | TypeScript 5.x (Node 18+) | Reuses existing generator infra |
| Generators | `tsx scripts/generate-all.ts` (already wired) | Add 2 new TS files |
| Markdown injection | Custom regex on HTML comment markers | No MDX/AST needed, simple sed-equivalent |
| TS imports | `import counts from '../../../counts.json'` (resolveJsonModule) | Verify tsconfig |
| CI gate | `git diff --exit-code` after `npm --prefix website run generate` | New job step in `ci.yml` |
| Tests | `bats` for shell, manual + smoke for TS scripts | No new test framework needed |

### Constraints

- Do not break the existing `npm run build` pipeline (Docusaurus is the website's only build path)
- Keep `validate-counts.sh` runnable (used by tests + tools that don't have Node)
- Backward-compatible: nothing visible changes for end users, only the maintenance overhead disappears
- All changes must pass: `bash scripts/validate-counts.sh` + `bats tests/*.bats` + `npm run build`

## Constitution check

- [x] Follows project conventions (TypeScript strict, no `any`, kebab-case files)
- [x] Consistent with existing architecture (extends generator pipeline, doesn't duplicate)
- [x] No over-engineering (no new dep, no new tool, no new framework)
- [x] Tests planned (bats updates + smoke test of generate-counts.ts)

## Phases

### Phase 1 — Foundation: counts.json + generator (30 min)

Create the source of truth and prove the generator works in isolation. Nothing else changes yet — consumers still hardcoded.

**Files to create**:
- `website/scripts/generate-counts.ts` — scans `.claude/`, writes `counts.json` to repo root
- `counts.json` — committed first version (4 globals + 9 byDomain + 2 tests)
- `website/scripts/utils/counts-types.ts` — TS type for `Counts` interface (shared by consumers)

**Files to modify**:
- `website/scripts/generate-all.ts` — call `generateCounts()` first (before doc generation)
- `website/tsconfig.json` (if needed) — verify `resolveJsonModule: true`

**Validation**:
- `npm --prefix website run generate` produces `counts.json` matching real filesystem
- `git diff counts.json` is empty after a fresh regen on the committed state
- Smoke test: delete a fake command file → regen → counts.commands decreases by 1

**Done when**: `counts.json` exists, regenerable, schema documented in `counts-types.ts`.

### Phase 2 — TS consumers (30 min)

Wire the 5 TypeScript files to import from `counts.json`. Highest-leverage step: drift-impossible-by-construction for everything Docusaurus renders from TS.

**Files to modify**:
- `website/src/components/Stats.tsx` — replace `SOCLE_STATS` literal with computed-from-counts.json
- `website/src/components/FeatureComparison.tsx` — replace `'131', '63', '54'` with `counts.commands.toString()` etc.
- `website/src/pages/index.tsx` — replace `'131 Commands'`, `'63 Sub-Agents'`, `'54 Skills'`, `'30 Rules'` with template literals
- `website/sidebars.ts` — replace `'WORK (15)'`, etc. (9 lines) with `\`WORK (${counts.byDomain.work})\``
- `website/docusaurus.config.ts` — replace `Commands (131)`, `Agents (63)`, etc. (4 lines)

**Validation**:
- `npm --prefix website run build` succeeds with same output as before
- Manual: serve build, confirm Welcome page + nav + footer render correct numbers

**Done when**: 5 TS files have zero hardcoded count literals, build green.

### Phase 3 — Markdown markers + injector (1h)

Instrument the 7 Markdown files that hold static counts with `<!-- count:KEY -->NNN<!-- /count -->` markers and add the injector step to the generator pipeline.

**Files to create**:
- `website/scripts/inject-counts-md.ts` — walks a hardcoded list of `.md` files, replaces marker contents from `counts.json`

**Files to modify** (add markers around existing numbers):
- `website/docs/intro/index.md` — Key numbers table (4 lines) + Domains table (9 lines)
- `website/docs/intro/architecture.md` — 8 occurrences in tables/headings
- `website/docs/reference/cheatsheet.md` — footer
- `README.md` — L20, L363, L465 (test layout)
- `CLAUDE.md` — narrative count refs
- `docs/CHEATSHEET.md` — ASCII art header + footer
- `docs/ARCHITECTURE.md` — `## File structure (30 rules)` heading
- `website/scripts/generate-all.ts` — call `injectCountsMd()` after doc generation

**Skip** (representations of shell output, not real counters):
- `website/docs/intro/installation.md` `Commandes: 131` (it's the SessionStart hook output mock)
- `website/docs/intro/quick-start.md` same

**Validation**:
- `npm --prefix website run generate` rewrites markers correctly
- Tampering with one marker value → next regen restores it
- All marker placements verified by reading each file post-injection

**Done when**: 7 Markdown files have markers around all in-scope counters, injector idempotent.

### Phase 4 — CI gate + validate-counts cleanup (15 min)

Lock the system with a CI gate, prune redundant checks in `validate-counts.sh`, fix the CI YAML drift bonus.

**Files to modify**:
- `.github/workflows/ci.yml` — add "Counts gate" step: `npm --prefix website ci && npm --prefix website run generate && git diff --exit-code`. Fix L47 stale `258 tests` → either dynamic count or static phrase like "Bats: see job logs"
- `scripts/validate-counts.sh` — remove redundant Layer 1 checks for files now covered by gate (Stats.tsx, FeatureComparison.tsx, index.tsx, docusaurus.config.ts, sidebars.ts targets). Keep Layer 2 (global narrative scan) and the test-counters scan
- `tests/validate-counts.bats` — update or retire the 4-5 tests that asserted on Layer 1 file checks now removed. Keep all Layer 2 tests + the regression test

**Validation**:
- `bats tests/*.bats` → still 100% green (with potentially N-5 tests if some retired)
- `bash scripts/validate-counts.sh` → still exit 0 on a clean repo
- Smoke: introduce a drift in one TS file → CI gate would catch it (verify locally with `git diff --exit-code` failing)

**Done when**: CI gate active, `validate-counts.sh` lean, all tests green.

## Risks and mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Breaking the Docusaurus build pipeline | Low | High (blocks all docs deploys) | Run `npm run build` after each phase, not just at the end |
| `resolveJsonModule` not enabled in tsconfig | Medium | Low | Verify in Phase 1, easy fix |
| Markdown injection corrupts surrounding text | Low | Medium | Use precise regex with capture groups, smoke-test after Phase 3 |
| Removing Layer 1 checks introduces a regression vs. what gate doesn't catch | Medium | Medium | Keep Layer 2 scan; only remove Layer 1 for files where the gate provides equivalent or better coverage |
| `validate-counts.bats` test removal masks real coverage loss | Low | Low | Document each retired test in commit message + verify the gate covers the same scenario |
| New domain added → byDomain key missing → TS error | Medium | Low | Use `Record<string, number>` for byDomain (open shape) rather than literal union |
| CI gate flakes due to git config (line endings, etc.) | Low | Medium | Use `git diff --exit-code -- 'counts.json' 'website/...md' ...` with explicit paths |

## Estimated total

**~2 hours** (30 min Phase 1 + 30 min Phase 2 + 1 h Phase 3 + 15 min Phase 4 + 15 min for unforeseen).

## Rollback plan

Each phase is a separate commit. If any phase breaks:
- Phase 1 fails → revert; no consumer changed yet
- Phase 2 fails → revert; consumers go back to hardcoded literals (still correct)
- Phase 3 fails → revert markers via `git checkout`; injector simply not called
- Phase 4 fails → revert CI gate; system functional, no enforcement
