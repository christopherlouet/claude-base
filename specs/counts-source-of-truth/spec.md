# Spec: counts.json source of truth + CI gate

**Status**: Validated
**Date**: 2026-05-03
**Owner**: Chris

---

## Summary

Eliminate manual maintenance of counter numbers (commands, agents, skills, rules, domain subtotals, tests) scattered across the repo. Today, 5 TS files + ~8 Markdown files + CI summary YAML hardcode totals that drift silently and must be hand-synced. The Welcome page hero (`Stats.tsx`) drifted to 123/59/42/24 (real: 131/63/54/30) and was unnoticed for multiple versions because the validation script didn't include that file.

The fix: a single `counts.json` at the repo root, regenerated by the existing TypeScript generator pipeline (`website/scripts/generate-*.ts`) on every build, consumed directly by TS files, injected into Markdown via simple HTML comment markers, and locked by a CI gate that fails if the regenerator's output disagrees with the committed file.

## Goals

- **Zero manual sync**: adding a new command/agent/skill/rule does not require editing any number anywhere
- **Drift impossible by construction**: CI fails if `counts.json` is stale OR if any consumer file is out of sync
- **No regression on existing safety nets**: keep the Layer 2 narrative scan in `validate-counts.sh` for prose that we don't instrument
- **Backward-compatible URLs / public API**: no doc URL change, no breaking script removal

## Non-goals

- Centralize narrative prose like "the 131 commands handle..." — kept in prose, validated by Layer 2 scan only
- Replace the existing Markdown auto-generator (`generate-command-docs.ts` etc.) — already correct
- Add a TypeScript-aware MDX inject system — too much for the value
- Touch settings.json SessionStart hook — already dynamic and correct

## User stories

### US-1 (P1) — Adding a new command does not require editing any number

**As a** maintainer adding a new file under `.claude/commands/<domain>/<name>.md`
**I want** the website, README, CLAUDE.md and CI to reflect the new total automatically
**So that** I do not forget to bump 9 places and ship a drifted release.

**Given** a clean `main`, **when** I add `.claude/commands/dev/dev-newthing.md` and run `npm run build`,
**then** `counts.json` shows `commands: 132`, `commands.dev: 24`, and all TS/MD consumers reflect the new value.

### US-2 (P1) — CI catches stale counts before merge

**As a** PR author
**I want** CI to fail my PR if counts are out of sync
**So that** drift never reaches main.

**Given** a PR that adds a new agent without re-running the generator, **when** CI runs `npm run generate && git diff --exit-code`, **then** the job fails with a clear message pointing to the regenerated files.

### US-3 (P2) — Existing manual edits are preserved

**As a** maintainer with custom prose around counters
**I want** my surrounding text untouched
**So that** the regenerator only updates the marked numbers, not the description.

**Given** a Markdown file with `Catalog of <!-- count:commands -->131<!-- /count --> commands for ...`, **when** the regenerator runs after the count changes to 132, **then** only the digits between the markers change.

## Functional requirements

- **FR-1**: A `counts.json` file at the repo root contains the canonical totals (commands, agents, skills, rules), per-domain command subtotals (work, dev, qa, ops, doc, biz, growth, data, legal), and test counters (totalTests, testFiles).
- **FR-2**: A new TypeScript script `website/scripts/generate-counts.ts` produces `counts.json` from filesystem scans (`find` equivalents). Called by `generate-all.ts`.
- **FR-3**: The TypeScript consumers (`Stats.tsx`, `FeatureComparison.tsx`, `pages/index.tsx`, `sidebars.ts`, `docusaurus.config.ts`) import from `counts.json` instead of hardcoding values.
- **FR-4**: A second new TypeScript step `inject-counts-md.ts` walks Markdown files containing `<!-- count:KEY -->NNN<!-- /count -->` markers and rewrites the `NNN` from `counts.json`. KEY is `commands`, `agents`, `skills`, `rules`, `tests`, `testFiles`, or `commands.<domain>`.
- **FR-5**: The CI workflow (`.github/workflows/ci.yml`) gains a "Counts gate" step: runs `npm --prefix website run generate` then `git diff --exit-code` — fails if the generator's output diverges from what was committed.
- **FR-6**: Existing `validate-counts.sh` keeps Layer 2 (global narrative scan) but loses the redundant Layer 1 file-specific checks now covered by the gate. Tests in `validate-counts.bats` updated accordingly.
- **FR-7**: CI YAML stale "258 tests" string in `ci.yml:47` is fixed (computed dynamically OR replaced with a static phrase that does not need updating).

## Edge cases

- **EC-1**: Marker present but `counts.json` missing → injector errors with a clear message, fail loud
- **EC-2**: Marker malformed (mismatched open/close) → injector skips with warning, does not corrupt the file
- **EC-3**: Adding a new domain (e.g., `growth/` becomes 12) → generator writes the new subtotal to `counts.json` automatically (no schema update needed if we use a flat `commands_<domain>` naming or nested `commands.<domain>`)
- **EC-4**: Markdown file is auto-regenerated by `generate-command-docs.ts` AND has injection markers → the marker injection runs after the doc generation in `generate-all.ts` ordering
- **EC-5**: Counts.json import path: TS strict mode requires `resolveJsonModule: true` in tsconfig → verify pre-existence

## Entities

| Entity | Source | Shape |
|---|---|---|
| `counts.json` | Generated | `{ commands: number, agents: number, skills: number, rules: number, tests: number, testFiles: number, byDomain: { work: 15, dev: 23, ... } }` |
| Marker | In Markdown | `<!-- count:KEY -->NNN<!-- /count -->` where KEY is dot-path into counts.json |

## Success criteria

- **SC-1**: After implementation, deleting and recreating any `.claude/commands/*/foo.md` changes counts everywhere on next `npm run build` with zero manual edits
- **SC-2**: CI fails if `git diff --exit-code` after `npm run generate` is non-empty
- **SC-3**: All 19 existing `validate-counts.bats` tests still pass (or are intentionally updated with PR-documented changes)
- **SC-4**: No regression in the Docusaurus build (still produces same `build/` output, no new broken links)
- **SC-5**: Welcome page hero shows correct counts after merge

## Out of scope

- Refactoring `validate-counts.sh` from Bash to TS
- Changing the SessionStart hook
- Adding counters for new things (e.g., total LOC, total contributors)
- Multi-language counter labels (current EN-only since v1.31.0)
